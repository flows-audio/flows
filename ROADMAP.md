# Priorities

This is a direction for contributions, not a dated release schedule.

1. Reliable first-run installation, clear errors and reproducible builds.
2. Audio correctness: note/release behavior, sample playback, live changes,
   observation and automation under realistic instruments.
3. A concise language with accurate completion, examples and documentation.
4. The browser build: hosting, first-run guidance and device coverage
   alongside the desktop app, from the same core and protocol.
5. Windows standalone/VST3 platform adapters and actual host/device checks.
6. Linux desktop adapters, dependency setup and distribution testing.

Musical examples and usability reports are valuable alongside code. Large
language additions, alternative GUI frameworks and engine rewrites should
start with an issue and a small demonstrable need.

Wavetable editing, a global post-mix FX chain and sample time-stretch are not
implemented; they are not promises of this preview. The browser build has no
Live bridge and keeps API keys only for the current tab.
